0背景与目标

为什么要做"一个"通用的用户世界模型,而不是三个独立模型。

  • 目标:一个可扩展的 user world model,服务 general / health / education 三类个性化 agent,并且架构上能容纳新域。核心仍沿用 user_world_model 的思路——per-user LLM,在条件输入下模拟用户的反应。
  • 现有积累:general 域已有 OPD/OPSD per-persona 模拟器(PersonaMem-v1);health 域已有 digital-twin(Qwen3-4B,文本反馈 + 状态 token);个性化训练有 PROPER(population→group→user 分阶段框架)。
  • 三个新增设计:在 per-user LLM 之上加 ① user profile(结构化用户状态)、② user memory(显式记忆,RAG 检索)、③ structured output(用户反馈文本 + 用户状态描述)。
  • 两种模式:冷启动/快速初始化(由 metadata 直接初始化)与在线学习(随用户数据流式更新)。
本稿结论一句话 把用户拆成三件套:权重存 disposition(怎么反应)· profile 存可言说的当前状态 · memory 存事件事实;统一 I/O 为 (state, context, agent_action) → 反应文本 + 下一状态;用 PROPER 的 population→group→user 分阶段做初始化;训练以 SFT 打底、蒸馏降级为可选;最后用两阶段评测(内在预测 + agent 联动)度量。跨域统一发生在 profile/memory 表示层,而非权重层。

2统一抽象

三个域收敛到同一个输入-输出 schema;education 还恰好裂成对应另外两域的两半。

# 统一 I/O
输入 = ( user_profile , 检索到的 user_memory , context , agent_action )
输出 = {
  "reaction_text":  # 用户会说什么(三域共享,= 现在的模拟反应),
  "next_state":     # 动作之后的用户状态(可选结构化)
}
域next_state 是什么例子
healthwellness 状态(fatigue / mood / readiness…)agent:"去跑个 5k" → 反应文本 + 预测 fatigue↑
educationmastery / 对错 / 选中的 distractortutor 讲解 → 反应文本 + 预测该题作答
general(可空)→ 退化为候选打分assistant 回复 → 用户反应 + 满意度
为什么 next_state 让它配叫 "world model" 输出"动作之后的下一状态"而非当前状态,意味着模型在预测状态转移(不只是模拟一句话);并且闭环:预测出的 next_state 写回 profile.dynamic,就能做多步 rollout 模拟。这也是 §7 Stage-2"agent 用 UWM 做 lookahead 规划"的基础。

education 的对称裂解:edu-reaction(学生对 tutor 的文字反应,≈ general)+ edu-exam(预测作答/对错,≈ health 的结构化 state)。于是 health 的 state head 和 edu 的 exam head 是同一机制的两个实例。

3核心架构:三件套(profile / memory / weights)

三者最容易互相重叠——必须先钉死各自管什么、各自怎么"写"。

一条原则解决"更新"难题(避免滑向 agentic memory) 没有任何组件靠 LLM 决定"写"。所有"写"都是笨的,所有"智能"都在"读"那一侧——也就是 world model 本身,正好是研究主题。这把"搞复杂就偏题"的风险直接消除。
组件存什么写(update)读(use)
per-user 权重(LoRA)disposition:风格 / 偏好先验 / 体质·知识基线——"倾向于怎么反应"周期性 batch 重蒸(慢)参数化,隐式
user profile结构化当前状态:static(不变量)+ dynamic(身体/学习状态)确定性重算:extract(data)→profile,脚本/特征抽取模型读进 context 自己解释
user memoryepisodic:发生过什么、具体事实append-only:每个 turn/活动/考试直接追加RAG 按当前 context 检索

3.1 profile / weights 的边界 = 可言说性(verbalizability)

  • 能写成 slot 的 → profile(因此冷启动可注入、可编辑、可做反事实);写不下来的 → 权重(说话风格、品味、persona 的 gestalt)。
  • 不变量(性别/种族)放 profile 而非权重:① 冷启动要求它可注入而无需训练;② R1b 已证明 demographics 当输入有效;③ 用户模拟器需要它可换("如果这个用户更老会怎样")。
  • "存根不存视图"消掉大半更新:存 birth_year,age 在读取时算。凡随时间变的量,存不变的根、时变视图读取时算。

3.2 三件套都不做"写决策"

  • memory:写=笨(append),读=智能(RAG)。运动/考试等非对话事件也照样追加。
  • profile.dynamic:是对近期数据的确定性聚合(health=生理特征;edu=per-skill mastery,即 knowledge tracing)——是 memory 的"物化视图",重算即可,无 CRUD。
  • health 的 dynamic profile:倾向放原始生理特征(模型学怎么解读,Health-LLM 式序列化),把自报告(fatigue/mood)留作训练目标,不进输入。

5训练目标:SFT 打底,蒸馏降级为可选

加了 memory 之后,OPD 当初存在的理由被掏空了——必须重估 SFT vs 蒸馏。

核心论断 原 OPD work,是因为 student 推理时完全没有历史(只有 demographics),teacher 的特权 = 全部历史,使命是"把历史压进权重"。新架构里 student 有 profile + memory(RAG),历史不再缺失 → teacher 的历史特权大部分已直接给到 student → 蒸馏的边际价值下降。digital-twin 直接 SFT work,正因为它有精确标签、不缺 context、不需要 teacher。

5.1 OPSD 其实"≈ on-policy 的 SFT"

OPSD 把 GT 软注入 teacher,P(GT) 从 0.57→0.94。这意味着 teacher 分布 ≈ "看过 GT 后与 GT 一致的续写"——信息量上几乎就是 GT,只是软标签 + on-policy。这解释了它收敛快/稳(本质拟合 GT)、却整体不如 R1b(GT-conditioned teacher 没带来超出 GT 的知识)。

两种 teacher 要分清:不看 GT 的 teacher(R1b 式)必须真预测 → 才有"teacher 自己生成不好就没法指导"的 ceiling 风险;看 GT 的 teacher(OPSD)ceiling 低但 ≈ SFT。OPSD vs SFT 差的是 on-policy(缓 exposure bias),不是知识。

5.2 那么 OPSD 的"特权信息"该是什么?

特权信息(teacher 看 / student 不看)值得蒸?说明
oracle / 完整 memory vs student 的 bounded top-k RAG✅ 最干净蒸馏教 student 补上 RAG 召回不到的部分;原 OPD 的自然推广(从"零历史"到"部分历史")
post-hoc 标签 / 状态(health wellness GT、edu 考试结果)✅label-conditioned teacher 教 student 产出与隐状态一致的反应
更大 / 更强的 teacher✅标准能力蒸馏,与 context 无关
GT 本身(OPSD)⚠️ ≈ SFT只剩 on-policy 那点增益
原来的"全部历史"❌ 已失效现在被 memory 直接给 student 了

5.3 推荐配方:CE(GT) 打底 + 可选 KL

Loss = CE(GT)                              # 直接学真实反应,永不被 teacher 上限卡住
     + λ · KL(student ‖ teacher)          # 可选,仅当 teacher 有真特权时
  • 结构化状态输出(fatigue=4 这类精确标签)→ 几乎肯定走纯 SFT(监督回归/分类,无 teacher 必要)。
  • 自由文本反应→ CE(GT) + 可选 KL(oracle memory / 标签 / 更强模型)。
  • 这正是 §11.7 自己列为"尚未尝试"的 CE-on-GT mix,现在有了清楚动机。

6在线学习与 memory 路由

流式数据进来时,新事实进 memory、disposition 进权重;teacher 在这里的真实角色不是"被模仿",而是"防遗忘锚"。

online teacher = trust-region 防漂移锚(非 oracle) Loss = CE(GT)(学新反应)+ λ·KL(student ‖ frozen group teacher)(防遗忘)。KL 项的真实作用是把 user LoRA 拉住别漂走(continual learning 的 LwF 正则),teacher 不需要是好预测器——学习由 CE(GT) 负责。这同时回答了"teacher 生成不好怎么办"和"OPSD 为何能缓解灾难性遗忘"。此处反而不要 GT 注入:锚应代表稳定先验,而非追 GT。

新事实进 memory、不进权重——三块协同

  1. 存储不是决策。GT 一到就 append 进 memory——"新活动"这一刻已在 memory 里。真正的问题不是"怎么记",是"别塞进权重 + 让模型学会用它"。
  2. novelty gate 把新事实挡在权重外。门控对象换对:token 级"这段内容能否由 student 现有 context(profile+检索 memory)预测出来"。信号 = teacher 跑两遍(新事实在/不在 context 中可检索),两遍在 GT token 上的差异 → 精确定位"必须靠 memory 的 token",在蒸馏 loss 里降权。
    在线恰好解锁了离线做不到的 gate:§11.7 写过"没有 GT 就无法在 token 级区分 teacher 自信对/错";在线时手里就有 GT + memory 这两个原料。
  3. 教"用 memory"的技能。训练时:凡 GT 引用过去事实的 turn,就保证检索把它送进 student 的 context,训它"给定检索事实去反应"。于是 t 轮的新事实被挡在权重外、存进 memory;t+k 轮再提及时,memory 检索命中,学到的技能让 student 正确反应——全程没把事实背进权重。
净效果一句话 权重只学 disposition + "用 memory 的技能";memory 持有事实;novelty gate 当两者之间的路由器。实现上 build_opd_data 已按 turn 组装 context,只需再加一个 "retrieved memory" 字段从更早 turn 填充。

7两阶段评测

先量"模型自己预测得准不准",再量"配合 agent 是否更好"。

Stage 1 · 内在预测(recall + extrapolation)

给定条件,UWM 自己能否准确预测用户。两种输出类型:

输出任务示例指标
文本反应直接预测用户回复(general/edu/health)现有 MCQ-PPL / NLL / LLM-judge
结构化状态health:当前状态+运动 → 预测运动后状态;edu:知识水平 → 预测作答per-field 状态误差(仿 compute_state_metrics)/ 作答准确率·distractor 匹配
recall vs extrapolation 恰好分别探测两个组件 recall(已观测历史内)主要考 memory 是否 work;extrapolation(没见过的反应/状态)主要考 disposition 权重是否泛化。所以这个拆分不只是难度分层,而是把"事实靠 memory、风格靠权重"这条设计假设做成可证伪的测量(复用 within-K / beyond-K distance_to_ref 分层)。

Stage 2 · agent 联动(下游效用)

把 UWM 配给各域 agent,测 agent + UWM 是否优于单 agent。这是"world model"的真正回报,对应 UserLM(真实用户模拟器改变了对 agent 的测量,74.6→57.4)。

"better" 要先定清是哪条通道 ① UWM 当 planner/个性化信号(agent 推理时查 UWM"用户会怎么反应"来选动作)→ 这才是"更好";② UWM 当 evaluator(真实模拟器考 agent)→ 会让 agent 看起来更差(更诚实)。主线应取 ①。 
# Stage-2 最 "world model" 的落地:候选 lookahead 规划
agent 提 N 个候选动作
  → UWM 预测每个动作下的 用户反应 / next_state
  → agent 选 预测用户结果最好 的那个      # health=最佳 next-state · edu=最高理解度 · general=最满意
对比 baseline:agent-alone(无 UWM lookahead)

这正是 repo 现在"按 PPL 给 N 个候选打分"的规划化推广,三域统一。

9风险与待决策(讨论重点)

9.1 现实风险

  • 低数据域:health 仅 16 用户、edu 私有仅 66 session,撑不起 per-user 权重。对策:这些域更靠 context(profile+memory)+ 共享 base,权重特化作为"挣来的"附加;必要时合成用户。
  • competency bias:LLM 扮学生/用户会过度高级、情绪平淡。对策:用真实错误/distractor 分布(EEDI/ASSISTments)校准合成。
  • 灾难性遗忘:online 增量更权重会漂(Leilani 单调衰减是前车之鉴)。对策:CE(GT)+KL-to-frozen-anchor,且 memory 当 source of truth、权重周期性重编译。
  • 结构化输出 × per-user LoRA 冲突:§13 实测 LoRA 会破坏格式遵从(parse fail 5.4%→36-48%)。对策:格式/控制留在共享 base 或受限解码,per-user adapter 只移动内容分布。

9.2 待与合作者决策的开放问题

  1. 统一程度:确认"在 profile/memory 表示层统一、权重保持 per-domain"这条路线?
  2. population 广度:用 WildChat + pooled 跨域数据训宽 population(否则冷启动只对 20 个 persona 有效)?
  3. Base vs Instruct:先保 R3-Instruct + 记 ablation,还是认真试 Base?
  4. group 复杂度:极简(profile 硬指派 + 残差 init)先做,还是直接上 PROPER 的 β-软混合 MoE?
  5. 训练目标分工:确认"结构化状态走纯 SFT、文本反应走 CE + 可选 KL"?
  6. novelty gate 实现:用"teacher 跑两遍(有/无 memory)取 token 差"当第一版门控?
  7. 先打通哪个域:general 最熟、评估最全;health 数据管线最现成。建议 general 先打通全链路,health 第二个验证跨域。

9.3 建议的下一步

  1. 选定首个落地域,把 §3–§7 写成形式化方案(profile schema、memory schema、训练/评测协议、baseline、与 PROPER/digital-twin 的对比)。
  2. 在 general 域做消融骨架:base vs +profile vs +memory vs +per-user 权重——量化"权重在 profile+memory 之上的边际价值"(本身就是一个可发表问题)。
  3. health:把 digital-twin V3 删掉 HR 分支、接上 profile/memory,做第二个域的跨域验证。
